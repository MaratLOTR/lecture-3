# Bridge — Мост

**Дополнительный раздел для самостоятельного углублённого изучения.**
Основная практика курса завершается на Adapter, Facade и Composite.

## Проблема: две независимые оси расширения

В умном доме есть разные **виды управления**: обычный пульт, расширенный пульт,
пульт для презентаций. Есть разные **виды устройств**: телевизор, проектор, радио.

Если делать отдельный класс для каждой комбинации, появятся `BasicTVRemote`,
`AdvancedTVRemote`, `BasicProjectorRemote`, `AdvancedProjectorRemote` и так далее.
Добавление одного устройства потребует новых классов для всех видов пультов.

## Решение и роли

Пульт хранит ссылку на `MediaDevice` и делегирует ему низкоуровневые операции.
Иерархия пультов и иерархия устройств развиваются независимо.
Здесь «реализация» означает сторону устройств, а не конкретный подкласс пульта.

| Роль | Участник |
|---|---|
| Abstraction | `Remote` — включение и установка громкости |
| RefinedAbstraction | `AdvancedRemote` — дополнительная операция `mute()` |
| Implementor | `MediaDevice` — контракт устройств |
| ConcreteImplementor | `TV`, `Projector` |

```text
Remote ───── хранит ссылку ─────→ MediaDevice
  ↑                                ↑
AdvancedRemote                 TV, Projector
```

Оба пульта работают с обоими устройствами. Телевизор хранит громкость точно
в процентах; проектор имеет 10 ступеней и округляет значение вниз до десятков.
Например, команда 37% даёт 37% на телевизоре и 30% на проекторе.
Контракт `MediaDevice` явно допускает это округление.

```python
tv_remote = AdvancedRemote(TV())
projector_remote = AdvancedRemote(Projector())
tv_remote.mute()
projector_remote.mute()
```

## Код и запуск

- [remotes.py](remotes.py) — две стороны моста и задание.
- [__main__.py](__main__.py) — все сочетания готовых пультов и устройств.

Нужен Python 3.10+ и pytest 9+. В Codespaces pytest устанавливается автоматически.
Из этой папки паттерна (её можно передать студенту отдельно):

```bash
python3 __main__.py
pytest tests/test_example.py
pytest tests/test_task.py
```

`test_example.py` проверяет готовый пример, `test_task.py` — выполнение задания.
До выполнения задания вторая проверка выдаёт ошибки; это ожидаемо.

Из корня проекта по-прежнему работают `python3 -m patterns.bridge`
и команда `pytest tests/test_bridge.py` (пример и задание вместе).

## Углублённый разбор

Подготовьте объяснение по коду и ответьте на вопросы:

1. Где находятся две оси расширения? Какая ссылка соединяет их?
2. Какие классы пришлось бы добавить без моста при появлении радио?
3. Какие изменения нужны для третьего устройства и третьего пульта с мостом?
4. Почему в этом примере не нужны проверки `isinstance(device, TV)` внутри пультов?
5. Какова цена решения, если в системе всегда будет один пульт и одно устройство?

| Сравнение | Различие по задаче |
|---|---|
| Bridge и Adapter | Bridge заранее разделяет независимо изменяемые стороны; Adapter согласует уже существующие несовместимые интерфейсы |
| Bridge и Strategy | В этом Bridge независимо расширяются виды пультов и устройств; Strategy выделяет взаимозаменяемый алгоритм работы контекста |
| Bridge и наследование всех комбинаций | Композиция позволяет собрать сочетание пульта и устройства при создании объекта |

**Преимущество:** новый пульт не требует новых подклассов для каждого устройства.
**Недостаток:** появляются дополнительный интерфейс и делегирование; при одной
неизменяемой комбинации это может быть лишней сложностью.

Важно объяснять назначение паттерна: сама по себе ссылка одного объекта на другой
ещё не доказывает, что в программе применён Bridge.
