# Composite — Компоновщик

Пример: слайды 32–41; задание: слайд 43 презентации «Лекция 3».
Код ниже сохраняет операции со слайдов и дополняет их выводом дерева (`describe()`),
удалением элементов и защитой от циклов. На слайдах эти вспомогательные детали опущены.
Большое дерево на слайде 35 иллюстрирует вложенность; для задания используется
небольшое дерево со слайда 43, приведённое ниже.

## Проблема

В доме есть отдельные приборы, комнаты и этажи. Если хранить их как несвязанные типы,
клиенту придётся разбирать структуру вручную: найти комнаты, перебрать приборы,
отдельно обработать вложенные группы.

Нужна единая команда: выключить лампу, комнату или весь дом.

## Решение и роли

Устройство выполняет команду само, а группа передаёт её детям. Среди детей могут
быть как устройства, так и другие группы. Рекурсия проходит всё поддерево.

| Роль | Класс |
|---|---|
| Component — общий интерфейс | `Component`: `turn_on()`, `turn_off()`, `describe()` |
| Leaf — конечный элемент | `Device` |
| Composite — контейнер компонентов | `DeviceGroup` |

```text
Дом (DeviceGroup)
└── Первый этаж (DeviceGroup)
    ├── Гостиная (DeviceGroup)
    │   ├── Лампа (Device)
    │   └── Телевизор (Device)
    └── Кухня (DeviceGroup)
        └── Чайник (Device)
```

`house.turn_off()` выключает все приборы в доме.
`living_room.turn_off()` затрагивает только гостиную.
`lamp.turn_off()` выключает только лампу. Клиент использует одинаковую операцию.

Только группа имеет `add()` и `remove()`: устройство не обязано поддерживать
бессмысленную для него операцию добавления детей. Свойство `children` возвращает кортеж.
Чтобы перенести компонент, сначала вызовите `remove()` у старой группы.
Проверки в `add()` запрещают циклы, повторное добавление и двух родителей у одного компонента.

## Код и запуск

- [tree.py](tree.py) — общий интерфейс, лист и группа.

Из этой папки паттерна (её можно передать студенту отдельно):

python3 __main__.py
pytest tests/test_example.py
pytest tests/test_task.py

## Применимость и ограничения

Composite подходит для иерархий «часть — целое»: каталогов, меню, учебных программ,
групп элементов интерфейса. Клиенту не приходится отличать лист от контейнера
при выполнении общей операции. При этом общий интерфейс должен иметь смысл
для обоих видов компонентов; дерево также требует защиты от циклов.
